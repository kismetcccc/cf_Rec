## 部署

上传整个 cf_Rec（无需 .idea、__pycache__），另将原数据目录中 baby、sports、clothing 的 `<dataset>.inter`、`image_feat.npy`、`text_feat.npy` 复制到新目录 data/<dataset>/。只运行 Baby 可只复制 Baby 三个文件。不要复制历史 runs、mig_cache、user_graph_dict.npy 或重新划分数据。新目录没有内置真实数据。

从 cf_Rec 根目录执行：

```bash
# 优先激活此前成功运行实验的服务器环境，避免无必要升级 PyTorch。
python -m pip check
python -c "import torch,numpy,scipy,pandas,yaml; print(torch.__version__,torch.version.cuda); print(torch.cuda.is_available())"
sha256sum --ignore-missing -c docs/data-sha256sums.txt
# 确认本次需要的数据集三项均显示 OK；缺项不代表验证通过。
python main.py -m LGMRecOpt -d baby --seed 999 --set epochs=1
python main.py -m LGMRec -d baby --seed 999 --set epochs=1
# 正式复现，保留默认 1000 epochs、20 次早停等待，不沿用上面的 epochs=1。
for seed in 999 2026 2027; do
  python main.py -m LGMRecOpt -d baby --seed "$seed" || exit 1
done
```

新环境先安装与服务器驱动匹配的 PyTorch，再 `python -m pip install -r requirement.txt`。依赖范围不是精确锁文件。优先沿用历史环境，环境差异应记录并重新验证；本地版本见 environment-local.txt，不将 Windows 验证等同于 Linux 验证。

可用 `--data-dir /absolute/path/to/data` 指向已存在的数据根目录。每次自动创建唯一 log/runs/ 子目录；status.json 中须 finished=true、returncode=0、test_evaluated=false，checkpoint 文件存在。

## 复现口径

历史服务器环境（从原 status.json 提取，未在此机器重新安装）：Python 3.10.21、PyTorch 2.14.0+cu130、CUDA 13.0、NumPy 2.2.6、SciPy 1.15.3、RTX 4090。其他历史依赖未记录，不猜测版本。原始配置和种子 999 验证结果见 reference-baby-anchor-seed999.json。

Baby 三文件指纹已与历史服务器记录逐项核对一致。sports/clothing 清单来自现有本地数据，不能据此宣称历史成绩复现。

正式优化版参考 VALID R20：seed999=0.1015775264、seed2026=0.1030303420、seed2027=0.1008948928，三种子均值约 0.101834254；N20 均值约 0.043907213。此为历史结果，不是本次新跑成绩。README 中 B 为历史优化对照，不等同于当前原始 LGMRec 基线。

保持数据顺序、划分、特征、种子、batch=512、lr=0.002、weight_decay=0.00001、层数、alpha、早停和评估协议。不要为节省显存更改训练 batch 后仍称严格复现。CUDA 稀疏算子采用 warn_only 确定性设置，跨硬件/版本不承诺逐位一致；完整三种子均值和波动需服务器复跑确认，尚未制定统计容忍阈值。
