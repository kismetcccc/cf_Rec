# LGMRecOpt 模型审查与设备迁移修复

范围：models/LGMRecopt.py。审查 TRAIN 共现构图、锚点成员索引、注意力归一化、超边双向传播、用户历史均值、行为残差、BPR 与正则及设备迁移。

发现并复现：在 CPU 构造后调用 model.to('cuda')，adj、norm_adj、num_inters 为普通属性，不随模型移动，稀疏乘法报 CPU/CUDA 不一致。默认入口直接在目标设备构图，不受该路径影响。

修复：三个张量注册为 persistent=False 的 buffer，迁移时自动移动，仍从 TRAIN 重建、不新增检查点状态。清理权重函数未使用的 mask/counts 局部变量。未改变模型公式、超参数、初始化或训练协议。

验证：
- 稀疏超图输出及梯度与独立稠密公式 D^-1 H^T H X 一致（H 为按超边行归一化的注意力矩阵，D 为物品接收质量）。
- CPU -> CUDA 前向/反向 -> CPU 通过，strict 状态加载通过；图未写入 state_dict。
- 三种子与旧选定锚点实现的初始化/RNG/损失/梯度/两步 Adam/推理精确一致。
- 全部 Python 源码语法检查通过。
- 修复前真实 Baby 数据两模型各一轮 CUDA 训练、VALID 评估与检查点保存完成，日志在原仓库 test_runtime/final-audit-20261015-163211；这不是完整收敛复现。修复后默认计算保持等价，另做合成 CLI 验证。

没有发现当前默认配置下其他已确认的计算错误。不把实现正确性认定为算法涨点。未执行新的完整三种子收敛实验，未评估 TEST。CUDA index_add 等稀疏操作可能存在跨设备数值差异。
